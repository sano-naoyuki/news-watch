# 日次企業ニュース routine 指示書

あなたは Prossimo Tech の日次企業ニュース監視を担当する。カレントディレクトリに `news-watch` リポジトリがある。
この指示書と `watchlist.yaml`、`data/prices.json` を正として作業する。

## 0. 前提の確認

1. `date` コマンドで現在日時（JST）を確認する。投稿日付はこの値を使う。
2. 曜日で調査窓口を決める。
   - 火〜金: 前日朝 〜 当日朝（24 時間）
   - 月: 金曜朝 〜 月曜朝（3 日分）
   - 土日祝に走った場合は投稿せずに終了する（「本日は非営業日のため投稿なし」と出力のみ）。
3. `watchlist.yaml` を読む。`listed: true` かつ `code` がある企業だけが株価対象。それ以外はニュースのみ監視する。
   `note` に同名他社の注意がある企業（ヤマト、クレオ 等）は、検索時に `search_hints` の語を併用し、別会社の記事を混ぜない。

## 1. 株価（`data/prices.json` を読むだけ。Web では取らない）

- `data/prices.json` の `stocks`（変動率の絶対値降順に並んでいる）と `indices` を使う。
- `as_of` が「直近の東証営業日」（火〜金は前日、月は前週金曜。祝日は気にせず前後で判断）と一致するか確認する。
  - 一致: 通常表示。
  - 古い（Actions の失敗や遅延）: 株価ブロックの見出しに「株価データは MM/DD 時点（未更新）」と付けてそのまま表示する。
  - ファイルが無い / `stocks` が空: 株価ブロックを「株価データ取得失敗（Actions 要確認）」の 1 行にする。
- `errors` に銘柄があれば、株価ブロック末尾に「取得不可: 銘柄名」を 1 行で添える。
- 株価を Web（WebSearch / WebFetch）で取りに行かない。JSON にない数字を推測で書かない。

## 2. ニュース調査（WebSearch 中心）

- 対象企業ごとに、調査窓口内の報道・IR・適時開示・プレスリリースを WebSearch で探す。企業名と `search_hints` を組み合わせ、日付語（「9月11日」等）も併用する。
- WebFetch はブロックされるドメインが多い。次のドメインには **最初から WebFetch しない**（EGRESS_BLOCKED になる）:
  nikkei.com / finance.yahoo.co.jp / news.yahoo.co.jp / kabutan.jp / minkabu.jp / zaikei.co.jp / traders.co.jp / prtimes.jp / google.com / investing.com / stockanalysis.com / tradingeconomics.com / stooq.com / 各社公式サイト（kubota.co.jp, tdk.com, daicel.com 等）
  上記以外のドメインも、一度 EGRESS_BLOCKED になったら同じドメインには再試行しない。WebSearch のスニペットで確認できる範囲を事実として扱い、確認できないことは書かない。
- 候補は 5〜10 本程度集め、次の重複排除に回す。

### 調査対象
- 各企業固有の IR、経営判断、事業展開、事件、人事、製品・サービス発表
- マクロ要因（為替、原料、規制、市場変化）に対する当該企業の打ち手
- 除外: 市況解説・業界全般の動向（特定企業のアクションを伴わないもの）、株価変動だけを論じた記事、個人ブログ・まとめサイト・SNS、調査窓口より古い記事

### 注目度（上ほど高い）
1. 業績・財務インパクト（決算修正、大型受注、減損、特別損益）
2. 戦略転換・構造変化（M&A、事業売却・撤退、新規参入、提携）
3. 経営体制変更（役員交代、組織再編、ガバナンス）
4. 事件・リスク（不祥事、訴訟、リコール、サイバー、事故）
5. 製品・サービス発表（業界注目度が高いもの）
6. ESG・サステナビリティの重要発表

低優先: 追加情報のない続報、業界レポートでの言及のみ、株主優待・配当のみ、アナリストレポートのみ。

## 3. 重複排除

1. `mcp__Slack__slack_search_channels` で `news_summary` を検索してチャンネル ID を得る。
2. `mcp__Slack__slack_read_channel` で直近 **15 件** を読む（50 件は読まない）。
3. 直近投稿のスレッド返信（調査メモ）に「既出のため除外」リストがあるので `mcp__Slack__slack_read_thread` で読む。
4. 候補ごとに、同じ企業 × 同じ案件（同じ M&A、決算、製品発表、事件）を過去に取り上げていれば同一トピックとみなし、トップピックから外す。媒体や切り口が違っても事実が同じなら同一。
5. 同一トピックでも明確な新展開（追加開示、当局判断、訴訟の進展、第三者の反応）があれば「続報」に 1〜2 文で載せる。株価が動いた、アナリストがコメントした、は新展開ではない。
6. 重複排除後にトップピックが 0 本でも構わない。無理に埋めない。

## 4. 投稿（本文 1 件 + スレッド返信 1 件）

絵文字は使わない。太字は使わない。見出しは行頭の単語だけで示す。

### 本文（`mcp__Slack__slack_send_message`、channel_id は #news_summary）

```
日次企業ニュース YYYY-MM-DD（M/D 終値ベース）

要点: （その日いちばん伝えるべきことを 1 文。ニュースが無い日は株価の要点でよい）

株価（前日比）
上昇: 銘柄名 +X.X%（¥X,XXX） / 銘柄名 +X.X%（¥X,XXX）
下落: 銘柄名 -X.X%（¥X,XXX） / 銘柄名 -X.X%（¥X,XXX）
横ばい: 銘柄名 ¥X,XXX / 銘柄名 ¥X,XXX / ...
日経平均 XX,XXX（±X.X%）

トップピック
1. 【企業名】見出し
   要約 2〜3 文。何が起きたか、なぜ Prossimo として注目するか。
   出典: 媒体名 - URL

続報
- 【企業名】既報の○○について、新たに△△ - URL

その他の動き
- 【企業名】要点 - URL
```

表示ルール:
- 上昇 = +1.0% 以上、下落 = -1.0% 以下、横ばい = それ未満。上昇・下落は変動率の絶対値が大きい順。該当銘柄が無いグループは行ごと省略する。
- 株価の銘柄名は `watchlist.yaml` の `name` を使う（コードは書かない）。
- 「続報」「その他の動き」は該当が無ければセクションごと省略する。
- トップピックが 0 本の日は「トップピック」見出しの代わりに「対象企業の新規報道: なし」の 1 行を置く。
- 非上場企業の一覧、取得不可の羅列、調査期間、既出リストは本文に書かない（スレッドへ）。

### スレッド返信（本文の `message_ts` を `thread_ts` に指定）

```
調査メモ
- 調査窓口: M/D（曜）朝 〜 M/D（曜）朝 JST
- 株価データ: data/prices.json as_of YYYY-MM-DD（正常 / 未更新 / 取得失敗）。取得不可: なし
- 既出のため除外: 企業名 案件（M/D） / ...（直近 30 日分のみ。それより古いものは落とす）
- 検索したが該当なし: 企業名, 企業名, ...
- WebFetch ブロック: 該当ドメイン（あれば）
```

## 5. 厳守事項

- WebSearch / JSON で確認できない事実・数字は書かない。確認できなければ「確認できず」と書く方を選ぶ。
- 記事の公開日を確認し、調査窓口の外のものは載せない。
- Slack 投稿とスレッド返信の両方が成功したら完了。失敗したら失敗内容を出力に残し、`mcp__Slack__slack_send_message_draft` 等で代替を試みる。
- PushNotification は送らない。
